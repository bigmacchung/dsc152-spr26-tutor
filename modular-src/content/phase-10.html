Level 46 — Lab 4 Part 1: airquality SLR + LINE diagnostics + Type I simulations +70 XP
Business Story

You're handed R's built-in airquality dataset — 153 daily air-quality measurements from the New York metro area, May–September 1973. After dropping rows with missing values you have n = 111 complete days. Question: does temperature predict ozone concentration? A picture-perfect setup for simple linear regression. But the LINE conditions WILL be violated — and the lab forces you to feel exactly what each violation costs.

R Code — Lab 4 setup
aq <- na.omit(airquality)
cat("Rows:", nrow(aq), "\n")   # 111
head(aq)

# SLR: Ozone on Temp
model <- lm(Ozone ~ Temp, data=aq)
summary(model)
# Coefficients:
#               Estimate  Std. Error  t value  Pr(>|t|)
# (Intercept)  -147.65    18.76       -7.87    2.76e-12
# Temp            2.44     0.24       10.19    <2e-16    ***
The 2.44 trap. What is 2.44? It's \(\hat\beta_1\) — the SAMPLE estimate of the population slope \(\beta_1\). NOT the true slope. NOT a causal effect. Just our best guess from this n=111 sample of summer days.
Even with p < 2e-16, you cannot say "\(\beta_1\) is exactly 2.44." You can say "we are confident \(\beta_1\) is not zero." That's it.
⚠️ The classic Lab 4 LINE multiple-choice trap

Lab 4 Q1.4 lists four LINE statements. Three of them are tempting traps. The truths:

  • ✅ With n=111, CLT helps β̂₁ be approximately normal — t-test stays approximately valid even if residuals aren't perfectly normal.
  • ✅ E (equal variance) is broken if ozone is more variable on hot days than cool days. (It IS broken in airquality — see fan in residuals-vs-fitted.)
  • ❌ If I (independence) fails, the t-test does NOT give correct p-values. Standard errors are biased.
  • ❌ L (linearity) does NOT require β₁ ≠ 0. Linearity is about the SHAPE of the relationship, not whether one exists.
Reading the Two Diagnostic Plots

R's plot(model, which=1) is the residuals-vs-fitted plot. plot(model, which=2) is the Normal Q-Q plot. For airquality:

  • Residuals-vs-fitted: shows BOTH curvature (L violated — relationship is somewhat nonlinear) AND a clear fan (E violated — bigger residuals at higher fitted ozone). Answer to Lab 4 Q1.5: c(1, 4).
  • Q-Q plot: shows departure from the diagonal — N is violated. Q-Q plots specifically diagnose Normality. Answer to Lab 4 Q1.6: c(3).
R Code — Type I error simulation harness (Lab 4 Q1.7)
# Reusable simulator: takes ANY data generator, counts rejection rate at α=0.05
sim_typeI <- function(gen_data, reps, alpha = 0.05, ...) {
  args <- list(...)
  rejections <- replicate(reps, {
    dat <- do.call(gen_data, args)
    fit <- lm(dat$y ~ dat$x)
    p_val <- summary(fit)$coefficients[2, 4]
    p_val < alpha
  })
  mean(rejections)
}

# Baseline: all LINE conditions hold (β1 = 0, normal noise)
gen_baseline <- function(n, sigma) {
  x <- runif(n, 0, 10)
  y <- rnorm(n, mean=0, sd=sigma)   # slope IS zero
  list(x=x, y=y)
}

typeI_baseline <- sim_typeI(gen_baseline, reps=2000, n=50, sigma=2)
# typeI_baseline ≈ 0.05  ← when conditions hold, test is valid
replicate(reps, {...}) is R's idiomatic loop for Monte Carlo. It runs the block reps times and returns a vector.
do.call(fn, list(...)) calls fn with arguments unpacked from a list — lets you forward arbitrary args from outer to inner.
Same skeleton recycled for every condition violation: just swap out gen_data.
Quiz
You replace gen_baseline with a generator that produces heteroskedastic noise (sd grows with x). You run sim_typeI with reps=2000. The rate comes out around 0.12. What does this tell you?
"H₀ is true 12% of the time."
"The simulation has a bug — Type I error can never exceed α."
"Heteroskedasticity has inflated the test's actual Type I rate from the nominal 5% to about 12%. The test is INVALID under this violation — false positives are 2.4× more common than the test claims."
"With more reps the rate would drop back to 0.05."
Level 47 — Lab 4 Part 2-3: Confounding in airquality + cost of adjustment +70 XP
Business Story

Same dataset, new question: does solar radiation affect ozone? A clean SLR lm(Ozone ~ Solar.R) says yes — solar's coefficient is ~0.13, statistically significant. Smug? Don't be. Add temperature: lm(Ozone ~ Solar.R + Temp) and the solar coefficient SHRINKS. Why? Hot days are sunny days. Temperature was confounding the relationship, just like AGE confounded smoke→FEV in Lec 8. The story repeats with different costumes.

R Code — the confounder reveal
# Naive: solar alone
naive <- lm(Ozone ~ Solar.R, data=aq)
summary(naive)$coefficients
# Solar.R    0.127    0.030    4.27    p < 0.001  ← apparent positive effect

# Adjusted: solar AND temp
adjusted <- lm(Ozone ~ Solar.R + Temp, data=aq)
summary(adjusted)$coefficients
# Solar.R    0.052    0.026    1.97    p ≈ 0.05   ← solar effect SHRINKS by ~60%
# Temp       2.18     0.23     9.41    p < 0.001  ← temp dominates

# Confidence interval for the solar coefficient (adjusted)
confint(adjusted, "Solar.R")
The naive solar coefficient (0.127) was inflated by ~2.4× because of confounding with temperature.
After adjustment, solar's "real" effect (0.052) is barely significant — and the CI brushes zero.
This is the SAME shape as the FEV (Lec 8) story. Temp here = age there. The pattern repeats whenever a third variable predicts both X and Y.
Lab 4 Part 3 — Simulation of confounding under known DGP

Part 3 builds confounding from scratch: simulate (X, Z, Y) where Z is a confounder. Compare:

  • lm(y ~ x): BIASED estimate of the X→Y effect (because Z's variance leaks in)
  • lm(y ~ x + z): UNBIASED estimate (we condition on Z)

Under a known DGP you can verify: the bias disappears when you adjust. But you also see the COST: when X and Z are highly correlated, the standard error on β̂_x balloons (variance inflation). Adjustment isn't free.

The Bias-Variance Tradeoff in Confounder Adjustment
  • Skip adjustment: smaller SE, biased point estimate (the apparent solar effect of 0.127)
  • Adjust: larger SE (especially if X and Z are correlated), unbiased point estimate (0.052)
  • The math: \(\text{Var}(\hat\beta_x \mid x, z) = \dfrac{\sigma^2}{(1 - r_{xz}^2)\sum(x_i - \bar x)^2}\) — the (1 − r²) is the "variance inflation factor." High correlation between X and Z → small denominator → huge variance.
Analogy — Two Witnesses Telling Overlapping Stories

Imagine two witnesses describing a crime — both saw partly the same thing. If you ask only one (the naive model), they over-claim because they include shared and unique information mixed together. If you ask both (the adjusted model), each can only contribute their UNIQUE piece, but the more they overlap (high correlation), the less unique signal remains for each — your confidence in either's individual contribution drops. Adjustment makes the answer more honest but less precise when overlap is high.

Cross-reference: Step 7.5 Simpson's Paradox detector

The simpsons_paradox.py helper from the validation pipeline scans for SIGN REVERSALS between aggregate and segmented analyses. The airquality solar-ozone case here is a magnitude-shrinking confounder (effect goes from 0.13 to 0.05) — not a sign flip. Compare to Lec 8 PENGUINS where the slope literally flipped sign — that's the "high severity" Simpson's paradox. The detector's severity field would call airquality "low/medium" (effect modification) and penguins "high" (paradox).

Quiz
You adjust for temperature and the solar coefficient drops from 0.127 to 0.052 with p ≈ 0.05. The CI for solar (adjusted) is roughly (0.001, 0.103). What's the most defensible conclusion?
"After adjusting for temperature, there is weak/marginal evidence that solar radiation is associated with ozone (β̂ = 0.052, p ≈ 0.05, 95% CI: [0.001, 0.103]). The naive analysis substantially overstated solar's effect because temperature confounds the relationship. Even the adjusted CI brushes zero — claims about solar's role should be tentative."

Level 48 — Lab 5 Part 1: iris partial F-test (categorical species, by hand) +70 XP
Business Story

Famous Fisher iris dataset: 150 flowers, 50 each of setosa, versicolor, virginica. You want to predict petal length from species AND petal width. Species is categorical with 3 levels. R fits the model. You see TWO species coefficients in summary() output. The instinct is to read those p-values. That instinct is wrong. The correct test for "does species matter at all?" is the partial F-test — and Lab 5 makes you compute it BY HAND from RSS values to drive that home.

The Right Model

With setosa as reference (R's default — alphabetical), the model is:

\[\text{Petal.Length}_i = \beta_0 + \beta_1 \cdot \text{versicolor}_i + \beta_2 \cdot \text{virginica}_i + \beta_3 \cdot \text{Petal.Width}_i + \epsilon_i\]

where versicolor and virginica are 0/1 dummy indicators. setosa is captured by the intercept (both dummies = 0). Lab 5 Q1.1 answer = 2.

The Right Test for "Does Species Matter?"

The two species t-tests in summary() answer "is versicolor different from setosa?" and "is virginica different from setosa?" — separately, with no Bonferroni correction. The JOINT question — "does species, taken as a whole, help predict petal length after adjusting for petal width?" — is the partial F-test:

\(H_0: \beta_{\text{versicolor}} = \beta_{\text{virginica}} = 0\) (both species dummies are zero)

Compare full lm(Petal.Length ~ Species + Petal.Width) vs reduced lm(Petal.Length ~ Petal.Width) via anova(). Lab 5 Q1.2 answer = 3.

R Code — partial F by hand AND via anova()
data(iris)
full    <- lm(Petal.Length ~ Species + Petal.Width, data=iris)
reduced <- lm(Petal.Length ~ Petal.Width,           data=iris)

# Step 1: RSS for each model
RSS_full    <- sum(residuals(full)^2)
RSS_reduced <- sum(residuals(reduced)^2)

# Step 2: degrees of freedom
n <- nrow(iris)             # 150
k <- length(coef(full))     # 4 (intercept + 2 dummies + petal.width)
p <- length(coef(full)) - length(coef(reduced))  # 2 (the 2 species dummies)

# Step 3: F statistic
F_stat <- ((RSS_reduced - RSS_full) / p) / (RSS_full / (n - k))

# Step 4: upper-tail p-value from F(p, n-k) distribution
pval <- pf(F_stat, df1=p, df2=n - k, lower.tail=FALSE)

# Step 5: verify against built-in
anova(reduced, full)
# Both should match: large F, tiny p — species matters.
pf(q, df1, df2, lower.tail=FALSE) — upper-tail F probability. Same family as pt, pbinom from earlier lectures.
length(coef(model)) — programmatic way to count coefficients (don't hard-code).
anova(reduced, full) — pass smaller (nested) model FIRST, full model SECOND. The order matters for sign of degrees of freedom.
Analogy — Three Parallel Lines

Geometrically, the model Petal.Length ~ Species + Petal.Width draws THREE parallel lines (one per species) — same slope on Petal.Width, different intercepts. The vertical separation between the lines IS the species effect. The partial F-test asks "are these three lines really separated, or could that vertical spread be noise?" The huge F → no, the spread is real; species matters even after Petal.Width is controlled for.

⚠️ Lab 5 Q1.7 trap

"F > 1 means significance" is FALSE. Whether F is significant depends on its position in the F(p, n−k) distribution. F > 1 is just "the full model fits better than the reduced" — but you need the p-value to know if it fits "significantly" better. Q1.7 answer = 2.

Quiz
You fit lm(Petal.Length ~ Species) (no Petal.Width) and the partial F-test (vs intercept-only) gives a HUGE F. You then add Petal.Width and re-run partial F (vs Petal.Width only) — the F is still huge but smaller. What does this mean?
"Adding Petal.Width broke the model."
"Some of what species 'explained' on its own was actually mediated by petal width (different species have different typical widths). After adjusting for width, species's INDEPENDENT contribution is smaller but still strongly significant."
"Petal.Width is a confounder."
"You should drop Petal.Width since it reduced species's effect."
"The two F values should be identical."
Level 49 — Lab 5 Part 2 + Master Lab Cheat Sheet +90 XP
LINE in Multiple Regression — same letters, same diagnostics

The L·I·N·E conditions transfer from SLR to MLR with no real change. The diagnostic TOOLS are unchanged: residuals-vs-fitted (L + E), Q-Q plot + Shapiro-Wilk (N), residuals-vs-order (I). Only the geometric meaning of "fitted value" changes — it's now a higher-dimensional surface. Everything else is identical.

R Code — Lab 5 Part 2: simulation of L violation cost
# Generator: TRUE relationship is quadratic, but we fit a LINE
gen_quadratic_truth <- function(n, sigma) {
  x <- runif(n, 0, 10)
  y <- 2 + 3*x - 0.3*x^2 + rnorm(n, 0, sigma)
  list(x=x, y=y)
}

# Compare: power to detect ANY effect (slope ≠ 0)
# vs simulating a true linear effect at the SAME effective effect size
power_quad <- sim_typeI(gen_quadratic_truth, reps=2000, n=50, sigma=2)
# power_quad < what you'd get from a properly-specified linear model
# Lesson: ignoring curvature COSTS you power, even when the test is "valid."
R Code — Lab 5 Part 2: simulation of E violation impact on Type I
# Generator: TRUE slope = 0, but residual variance grows with x (heteroskedasticity)
gen_hetero <- function(n) {
  x <- runif(n, 0, 10)
  y <- rnorm(n, 0, sd=0.5 + 0.5*x)   # sd grows with x
  list(x=x, y=y)
}

typeI_hetero <- sim_typeI(gen_hetero, reps=2000, n=50)
# typeI_hetero > 0.05  ← the t-test rejects MORE than 5% of the time when H₀ is true
# The advertised α=0.05 is a lie. Real Type I might be 0.08-0.15 depending on severity.

⚠️ Lab Pitfalls — the recurring mistakes graders see
  1. Hard-coding n, k, p instead of computing them programmatically (Lab 5 Q1.5 explicitly tests this — points off if you write n <- 150 instead of n <- nrow(iris)).
  2. Reading per-row p-values when the question demands a partial F (Lab 5 Q1.2).
  3. Forgetting lower.tail = FALSE when computing F p-values — you'll report 1 - p instead of p.
  4. Computing the F-statistic with reduced and full backward (small ÷ big instead of (red - full) ÷ full).
  5. Concluding "no effect" when failing to reject — confused with "evidence of no effect." Lec 5 warning.
  6. Ignoring diagnostic plots and just reporting p-values — Lec 10 / Lab 5 Part 2 explicitly punish this.
Final Lab Mantra

Every lab in this course follows the same loop:

  1. Frame the question (which β are we testing? what's H₀?)
  2. Fit the model (lm or t.test — same tilde syntax)
  3. Extract the right p-value (single coef or partial F?)
  4. Check conditions (plot(model), simulation if you doubt them)
  5. Write a HONEST conclusion (estimate + CI + p-value + adjustment language + observational caveat)

Once you internalize this loop, every lab + every quiz question reduces to "which step is this asking about?"
