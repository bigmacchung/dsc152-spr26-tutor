Practice — read each line out loud
x <- c(10, 20, 30, 40)
# "x GETS combine 10, 20, 30, 40"
# Result: a vector with 4 slots → [10, 20, 30, 40]

length(x)
# "length of x" → 4 (the count of items)

x[2]
# "x at position 2" → 20

x >= 25
# "x greater than or equal to 25"
# Result: FALSE FALSE TRUE TRUE  (one TRUE/FALSE per slot)

x[x >= 25]
# "x at positions where x is >= 25"
# Result: 30 40  (keeps only the slots where TRUE)

sum(x >= 25)
# "sum of x >= 25"
# TRUE = 1, FALSE = 0, so sum = 0 + 0 + 1 + 1 = 2 (count of TRUEs)

mean(x >= 25)
# "mean of x >= 25"
# = 2 TRUEs / 4 total = 0.5 (PROPORTION of TRUEs)
Dataframes — your R version of Excel
df <- data.frame(
  name = c("Ana", "Ben", "Cara"),
  age  = c(21, 25, 19)
)
# df is now a 3-row, 2-column table:
#   name   age
#   Ana    21
#   Ben    25
#   Cara   19

df$age
# Pull out the age column → c(21, 25, 19)

df[df$age >= 20, ]
# Keep rows where age >= 20
# The comma + nothing-after = "all columns"
# Result: Ana 21, Ben 25  (Cara dropped — she's under 20)

df$age[df$name == "Ben"]
# "Give me the ages from the rows where name is Ben"
# Result: 25
⚠️ Common confusion: = vs == vs <-
  • <- = "gets" (assignment). Stores a value: x <- 5.
  • = = also assignment, but inside function calls it means "named argument": mean(x = my_data). Most R style guides prefer <- for top-level assignment.
  • == = "is equal to?" (a TRUE/FALSE question). NEVER use for assignment.

If you type x = 5 on a top line, R will assign. But if you type x == 5, R asks "does x equal 5?" and returns TRUE/FALSE.

Level 66 — 🧒 Functions, Loops & Simulation Tools (numeric, for, sample, replicate) +95 XP
Functions — recipes you write yourself
add_one <- function(x) {
  x + 1
}
# Read out loud: "add_one GETS a function that takes an input called x.
#                 It returns x + 1."

add_one(5)
# Output: 6
  • The word function tells R "I'm defining a recipe."
  • The thing in parentheses (here x) is a placeholder name. It only exists INSIDE the function. You can name it anything.
  • R returns the LAST line automatically. You don't need to write return(...).
The numeric() function — empty containers
numeric(5)
# Output: 0 0 0 0 0  (a vector of 5 zeros)

numeric(1000)
# Output: 0 0 0 ... 0  (one thousand zeros)

Why pre-create zeros? Because we know we will fill them with results from a loop. Pre-allocating is faster than growing a vector one item at a time.

Visual: imagine N empty boxes lined up, each labeled "0." Later, we replace each "0" with our real result.

The for loop — repeat a block N times
for (i in 1:5) {
  print(i * 10)
}
# Prints:
# 10  (round 1, i=1)
# 20  (round 2, i=2)
# 30  (round 3, i=3)
# 40  (round 4, i=4)
# 50  (round 5, i=5)
  • 1:5 = a shortcut for c(1, 2, 3, 4, 5).
  • i is just a counter — a variable that takes each value of 1:5 in turn.
  • Use i as your slot pointer: my_vec[i] means "the i-th slot of my_vec."
Loop + container pattern (the simulation skeleton)
results <- numeric(3)        # empty: [0, 0, 0]

for (i in 1:3) {
  results[i] <- i * i      # on round i, store i*i in slot i
}

print(results)
# Output: 1 4 9
# After round 1: [1, 0, 0]
# After round 2: [1, 4, 0]
# After round 3: [1, 4, 9]

This is the SAME pattern used by permutation tests, power simulations, and bootstrap.

The sample() function — shuffle or draw
x <- c("A", "B", "C", "D", "E")

sample(x)
# Output: e.g. "C" "A" "E" "B" "D"
# With no size argument, default is length(x), and default replace=FALSE.
# This is a TRUE SHUFFLE: every item used once, just in a new order.

sample(x, size = 3, replace = FALSE)
# Output: e.g. "B" "D" "A"  (3 items, no repeats)

sample(x, size = 5, replace = TRUE)
# Output: e.g. "A" "A" "C" "E" "A"  (5 items, repeats allowed)
# This is what bootstrap uses.
SettingMeaningUsed by
replace = FALSE (default)Pick from a finite pool; each item used at most oncePermutation, simple random sampling
replace = TRUEPretend the pool is infinite; same item can repeatBootstrap
The replicate() function — repeat without writing a loop
three_rolls <- replicate(3, {
  sample(1:6, 1)         # roll one die
})
# Output: e.g. c(4, 2, 6) — a vector of 3 dice rolls

replicate(n, expr) = run expr n times, collect results into a vector. Equivalent to writing a for-loop with a pre-allocated numeric vector, just shorter.

⚠️ Off-by-one trap

R is 1-indexed: the first slot is x[1], NOT x[0]. Python is 0-indexed (first is x[0]). Mixing these up is the #1 R bug for Python users.

What does replicate(100, mean(sample(x, replace=TRUE))) compute?
A permutation test
100 bootstrap means of the vector x — useful for a bootstrap CI
100 dice rolls
The sample mean of x, repeated 100 times
Level 67 — 🧒 Stats Vocabulary in Plain English (define-on-the-spot) +95 XP
Every word that scared you in Quiz 2, defined simply
Big wordPlain English
StatisticA number computed from your data sample. Example: the sample mean.
ParameterThe true population number you wish you knew. Example: the population mean μ.
Observed statisticThe statistic you actually computed from your real data. The number you saw.
Sampling distribution"What would the statistic look like if I redid the study 1000 times?" A made-up histogram of possible statistic values.
Null hypothesis (H₀)The boring claim. Usually "no effect" or "two things equal." This is what we ASSUME to compute p-values.
Alternative hypothesis (H_A)The interesting claim. The thing you hope is true.
Null distributionThe shape of the statistic IF the null hypothesis were true. In permutation tests, this is the histogram of 1000 shuffles.
p-value"How weird is my observed statistic, ASSUMING H₀ is true?" Small p = very weird = evidence against H₀.
Reject H₀"My data is too weird for H₀ to be plausible. I'll believe H_A."
Fail to reject H₀"My data isn't strange enough. I can't disprove H₀ (but I also haven't proven it)."
α (alpha)The cutoff for "weird enough." Usually 0.05. If p < α, reject H₀.
Type I errorFalse alarm. You rejected H₀ when H₀ was actually true.
Type II errorMiss. You failed to reject H₀ when H_A was actually true.
PowerThe probability of correctly catching a real effect. = 1 − P(Type II).
Confidence interval (CI)A plausible range for the true population value. 95% CI = "if we repeated the study many times, 95% of these intervals would contain the true value."
Standard error (SE)How "wobbly" your estimate is. Like the spread of the sampling distribution.
IndexA position number. x[3] = "the value at index 3."
Logical vectorA list of TRUE/FALSE values. Like c(TRUE, FALSE, TRUE).
ReplacementWhether items can be picked again. WITH replacement = each pick is independent, repeats allowed.
PermutationA rearrangement of items. In a 2-group permutation test, you reshuffle the GROUP LABELS while keeping the VALUES fixed.
BootstrapSampling WITH replacement from your data to estimate uncertainty (e.g., compute a CI for the mean).
ResidualThe "leftover" after the model predicts y. = actual y − predicted y.
SlopeHow much y changes when x goes up by 1. In lm, it's the coefficient on x.
CoefficientOne number in a fitted model. β̂₁ is "the coefficient on x₁." Each row of summary()'s table is a coefficient.
InteractionWhen the effect of x₁ DEPENDS ON the value of x₂. In R, written x1:x2 or x1*x2.
Main effectThe effect of one predictor, at the reference level of all others.
ConfounderA third variable that affects both your predictor and your outcome. Ignoring it biases the estimate.
Partial F-testTest that compares two nested models. Asks "do the extra coefficients in the bigger model help?"
Reference levelThe "baseline" category for a factor. By default R uses the alphabetically-first level. All other levels are compared TO this one.
LINE conditions4 assumptions for the t-test on a slope: Linearity, Independence, Normality (of residuals), Equal variance.
HeteroskedasticityBig word for "the spread of residuals changes with x." Breaks the E condition.
A "null distribution" is essentially...
A list of all observed values in your data
The distribution of y in your data
The shape (histogram) of your test statistic if H₀ were true — built either from theory or by simulation/shuffling
A standard normal distribution

Coefficients table (the heart): one row per coefficient. Columns are: Estimate (β̂), Std. Error (SE of β̂), t value (β̂ / SE), Pr(>|t|) (the p-value for H₀: β = 0).
The stars next to the p-value are R's way of saying "this is very/medium/slightly significant." Three stars = p < 0.001. One star = p < 0.05.
Residuals: shows the spread of (actual − predicted) values. Median near 0 and quartiles roughly symmetric = healthy fit.
R-squared: fraction of variance in y explained by the model. 0.58 means "the model explains 58% of the variability in y."
F-statistic + its p-value: tests "do ALL the predictors jointly help?" Different from per-row t-tests.
Extracting one number from summary()
model <- lm(y ~ x, data=df)
summary(model)$coefficients
# Returns the coefficient table as a matrix:
#               Estimate  Std. Error  t value  Pr(>|t|)
# (Intercept)   1.520     0.314       4.84     0.00001
# x             0.832     0.102       8.16     0.00000

summary(model)$coefficients[2, 1]
# "row 2, column 1" = the slope estimate β̂₁ = 0.832

summary(model)$coefficients[2, 4]
# "row 2, column 4" = the slope's p-value

summary(model)$coefficients["x", "Pr(>|t|)"]
# Same thing, but using row + column NAMES (safer than numbers)

Rule: [row, column]. For a coefficients table: rows = predictors, columns = (Estimate, SE, t, p).

anova(reduced, full) — partial F-test output
anova(reduced, full)

Analysis of Variance Table

Model 1: y ~ x2                        # reduced
Model 2: y ~ x1 + x2                   # full
  Res.Df    RSS  Df  Sum of Sq      F    Pr(>F)
1     48  72.13                                  # reduced
2     47  62.45   1     9.68     7.29   0.0096   # ← read THIS row
Always read row 2. Row 1 is just info about the reduced model. Row 2 is the actual TEST result.
Df = 1 means we added 1 coefficient going from reduced to full.
F = 7.29, Pr(>F) = 0.0096: the F-statistic and its p-value. Here p < 0.05 → reject H₀: extra coefficient = 0.
RSS = residual sum of squares. Smaller RSS = better fit. The drop from 72.13 to 62.45 measures how much the extra term improved the fit.
