Level 26 — Two-Sample t-Test (the parametric A/B test) +50 XP
Business Story

Your professor is running a real research study at UCSD: do students learn probability better with coding exercises or handwritten exercises? Every student takes a pre-test, gets randomly assigned to one group, takes a post-test. The outcome is the score change. You have two samples of numbers. Is the difference real or just luck? That is an A/B test — and the standard parametric tool for it is the two-sample t-Test.

Concept — One-Sample vs Two-Sample

In Lec 2 you tested whether ONE group's mean differs from a fixed number (e.g. "is mean sleep different from 6 hours?"). Now you have TWO independent groups and you want to know if their means differ from each other. The hypotheses become:

Hypotheses & Test Statistic

$$H_0:\ \mu_1 = \mu_2 \qquad H_A:\ \mu_1 \neq \mu_2$$

Welch's two-sample test statistic (the default in R's t.test):

$$t_s = \frac{\bar{x}_1 - \bar{x}_2}{\sqrt{\frac{s_1^2}{n_1} + \frac{s_2^2}{n_2}}}$$

Same shape as the one-sample stat: (observed effect) / (standard error of that effect). Under H₀ it follows a t-distribution.

Analogy — The Coffee-Cup Test

Imagine two coffee shops. You sip 5 cups from Shop A, 5 cups from Shop B, and ask: "Is one consistently stronger?" The numerator of t is "how different the average sips are." The denominator is "how much sips vary within each shop." If between-shop difference dwarfs within-shop noise, t is huge → small p-value.

R Code — Lec 6 worked example
# Coding-vs-Handwritten preliminary data (n=5 per group)
prob_df <- data.frame(
  score_diff = c(2,5,3,-3,8,   # handwritten
                 9,10,-1,14,6),  # coding
  group = c(rep("handwritten",5), rep("coding",5))
)

# The formula syntax y ~ x means "outcome by group"
t.test(score_diff ~ group, data=prob_df)
score_diff ~ group — Read aloud as "score_diff by group." Tilde always means "outcome on the left, predictor on the right." Same syntax you'll see for lm().
By default R uses Welch's version (NOT assuming equal variances). For the equal-variance "pooled" version, add var.equal=TRUE.
Output gives: t-statistic, df (often non-integer for Welch), p-value, 95% CI for the difference of means.
Validity Conditions (be ready to list these)
  • Independence — observations independent within AND between groups (random assignment guarantees this)
  • Normality of x̄ in each group — either each population is normal, OR each n is large enough for CLT to kick in
  • For pooled (var.equal=TRUE) only: equal population variances

"Validity" means: if H₀ is true, the test rejects at exactly rate α. Violations inflate (or deflate) the Type I error rate — the same simulation game you played in Lec 2.

Why Random Assignment Is the Whole Point

This is what separates a designed experiment from observational data. Random assignment makes the two groups equivalent in expectation on every covariate (measured AND unmeasured). So if a difference shows up after treatment, the treatment is a plausible cause. In observational data you can only ever say "associated with."

Quiz
In the coding-vs-handwritten study, suppose you find p = 0.03 from t.test(score_diff ~ group, data=prob_df). Which is the most defensible conclusion?
"Coding exercises cause better learning, and the effect is large."
"There is statistically significant evidence (α=0.05) that the two groups have different mean score changes; because of random assignment, this difference is causally attributable to exercise type."
"Because p<0.05, the alternative hypothesis is proven true."
"Effect sizes don't matter; only p-values do."
Level 27 — The Permutation Test (non-parametric A/B) + Interactive Shuffle +60 XP
Business Story

Same coding-vs-handwritten study — but suppose your sample is tiny (n=5 each) and you don't trust normality. Or the data is wildly skewed. You can't safely use a parametric t-test. Enter the permutation test: a non-parametric tool that makes no distributional assumptions. Instead it uses the data itself to build the null distribution by repeatedly shuffling the group labels.

Core Idea (memorize this sentence)

"If H₀ is true (no group effect), the labels are arbitrary — so any reshuffling of them is just as valid as the one we observed." The permutation test asks: among all possible re-labelings of the data, how extreme is our observed difference?

Analogy — The Card Deal

Picture 10 score-change values written on 10 index cards. You deal them into "handwritten" and "coding" piles by treatment label, compute the difference of means: that is your observed statistic. Now shuffle the labels and re-deal. Compute again. Repeat 1000 times. The fraction of shuffles whose absolute mean-diff is ≥ |observed| is your p-value. Random labels = pure null world.

Permutation p-value

$$p = \frac{\#\{\text{shuffles with } |\text{stat}_{\text{shuffled}}| \geq |\text{stat}_{\text{observed}}|\}}{\text{number of shuffles}}$$

If you enumerate ALL \(\binom{n_1+n_2}{n_1}\) permutations it's exact. With 1000 random shuffles it's approximate (Monte Carlo).

R Code — Permutation test (translation of the Python in DSC 10)
# 1) Function for the test statistic
diff_means <- function(df) {
  m_h <- mean(df$score_diff[df$group == "handwritten"])
  m_c <- mean(df$score_diff[df$group == "coding"])
  m_c - m_h
}

obs_stat <- diff_means(prob_df)

# 2) Loop: shuffle labels, recompute, accumulate
n_reps <- 1000
null_dist <- numeric(n_reps)
for (i in 1:n_reps) {
  shuffled <- prob_df
  shuffled$group <- sample(prob_df$group)  # shuffle WITHOUT replacement
  null_dist[i] <- diff_means(shuffled)
}

# 3) Two-sided p-value
mean(abs(null_dist) >= abs(obs_stat))
sample(x) with one argument and no replace=TRUE = shuffle (sampling without replacement). This is the difference vs bootstrap, which uses sample(x, replace=TRUE).
numeric(n_reps) pre-allocates an empty numeric vector of length n_reps — the R "accumulator" pattern.
mean(abs(null_dist) >= abs(obs_stat)) — the proportion of shuffles with absolute test stat at least as extreme. mean() on a logical vector counts TRUEs as 1's.

Level 28 — t-Test vs Permutation: when each one wins +40 XP
The Decision Rule (memorize)

If the validity conditions for the parametric t-test are met, use the t-test — it has slightly more power. If conditions are violated (small n + skewed data, heavy tails, contaminated outliers), switch to the permutation test: it makes no distributional assumption, only that observations are exchangeable under H₀.

Analogy — The Calculator vs The Counting Game

The t-test is a calculator: plug numbers into a known formula, get a p-value instantly. Fast, but the formula assumes the world looks a certain way (normal-ish). The permutation test is a counting game: you act out the null world by shuffling, count how often the data looks at least this extreme. Slower (1000 shuffles), but the only assumption is "if H₀ is true, the labels are interchangeable." That's it.

Power Comparison — Lec 6 Slide

The professor's slide showed power curves under δ=4.5, σ=4 across n=5 to ~30. Both tests ramp up similarly; the t-test has a tiny edge when its conditions hold. The takeaway: permutation tests give up almost nothing in power but gain robustness when conditions break.

R Code — same data, two tests
# Parametric
t.test(score_diff ~ group, data=prob_df)$p.value

# Non-parametric — built from scratch above
mean(abs(null_dist) >= abs(obs_stat))
Trap — Permutation Doesn't Test the Same Thing

The permutation test under the "exchangeable labels" null actually tests "the two distributions are identical," which is stronger than "their means are equal." If the two groups have equal means but very different variances, the permutation test can still reject. That is technically a feature, but be precise about what H₀ really is when you write your conclusion.

Quiz
You have n=8 in each group, the data look strongly right-skewed in both groups, and your QQ plot of pooled data is curved. Which test do you reach for?
Welch's t-test, because n is "large enough" for CLT.
Permutation test — small n + skew means CLT hasn't kicked in, so the parametric assumption is shaky. Permutation needs no distributional assumption.

Level 29 — Simple Linear Regression: from data to a line +50 XP
Business Story

Spring 2019, Villanova University. The professor surveys n=50 students about their basketball knowledge (0–10 score) and then has them fill out an NCAA March Madness bracket. Brackets are scored ESPN-style. Question: does basketball knowledge predict bracket score? One quantitative outcome (bracket_score), one quantitative predictor (knowledge). This is the canonical setup for simple linear regression.

Concept — The Model

"Simple" means ONE predictor variable. We fit a line:

$$\hat{y} = \hat\beta_0 + \hat\beta_1 x$$

\(\hat\beta_0\) = intercept (predicted y when x=0). \(\hat\beta_1\) = slope (predicted change in y per +1 unit of x). The hat means "estimated from data" — these are statistics, not parameters.

⚠️ Notation: Statisticians vs ML
ConceptStats (DSC 152)ML (DSC 40A)
True intercept (population)\(\beta_0\)\(w_0^*\)
True slope (population)\(\beta_1\)\(w_1^*\)
Estimated intercept (from sample)\(\hat\beta_0\)\(w_0\)
Estimated slope (from sample)\(\hat\beta_1\)\(w_1\)
Word "parameter"True population quantity (β)Any input to a model (sloppy!)

A statistic = computed from data. A parameter = unknown population truth. β has no hat. β-hat does. Mix this up on the quiz at your peril.

Least Squares — the formulas

$\hat\beta_1 = \dfrac{\sum_i (x_i - \bar x)(y_i - \bar y)}{\sum_i (x_i - \bar x)^2}\qquad\hat\beta_0 = \bar y - \hat\beta_1 \bar x$

These minimize the residual sum of squares: \(RSS = \sum_i (y_i - \hat y_i)^2\). (In DSC 40A this was \(R_{sq}(w_0,w_1) = \tfrac{1}{n}\sum (y_i - (w_0 + w_1 x_i))^2\) — same thing up to a constant.)

Analogy — Squashing Springs

Imagine a spring connecting each data point to the line. Each spring's energy is proportional to the square of its stretch. The "best fit" line is the one where the springs collectively store the LEAST total energy. Squared (not absolute) distance is what makes it a clean, closed-form solution.

R Code — manually vs with lm()
# By hand
beta1 <- sum((knowledge - mean(knowledge)) *
              (bracket_score - mean(bracket_score))) /
         sum((knowledge - mean(knowledge))^2)
beta0 <- mean(bracket_score) - beta1 * mean(knowledge)

# With R's built-in
model1 <- lm(bracket_score ~ knowledge, data=march_madness)
summary(model1)$coefficients[2,1]   # β1-hat (matches manual!)
summary(model1)$coefficients[1,1]   # β0-hat (matches manual!)
lm(y ~ x, data=df) — the workhorse. Same tilde syntax as t.test.
summary(model)$coefficients is a 2×4 matrix: rows = (Intercept, x), columns = (Estimate, Std. Error, t value, Pr(>|t|)).
So [2,1] grabs the slope estimate; [2,4] grabs the slope's p-value.
Quiz

"For each correct game pick, basketball knowledge increases by 38.4 points."
"The true population slope is exactly 38.4."

Level 30 — Inference for the Slope: t-Test on β₁ + Interactive Sandbox +60 XP
From Modeling to Inference

Model building asks "what's the best line?" Statistical inference asks "is there even a real relationship?" In DSC 40A you stopped at the first question. Here we ask the second:

$$H_0:\ \beta_1 = 0 \qquad H_A:\ \beta_1 \neq 0$$

If β₁ truly equals 0, there's no linear association in the population — what we see in our sample is just noise.

The Test Statistic — same shape as before!

$$t_s = \frac{\hat\beta_1 - 0}{SE(\hat\beta_1)} = \frac{\hat\beta_1}{SE(\hat\beta_1)}$$

Compare with the one-sample t (Lec 2): \(t_s = \dfrac{\bar x - \mu_0}{s/\sqrt n}\). Identical structure: (estimate − null value) / (standard error of the estimate). Under H₀ this follows a t-distribution with \(n - 2\) degrees of freedom (we estimated 2 things: β₀ and β₁).

Analogy — Reading the lm Summary

Look at summary(model1). The "knowledge" row's Pr(>|t|) column is your p-value for H₀: β₁=0. The t value column is the test statistic. The Std. Error is SE(β̂₁). It's the SAME t-test we've been doing since Lec 2 — only the numerator changed from "sample mean" to "estimated slope."

R Code — read the slope's p-value
model1 <- lm(bracket_score ~ knowledge, data=march_madness)
summary(model1)
# Look at the row for 'knowledge':
#                  Estimate  Std. Error  t value  Pr(>|t|)
#   knowledge       38.4      ...         ...      0.0001  <-- our p-value

# Or grab it directly:
summary(model1)$coefficients[2,4]

Level 31 — LINE Conditions for Regression Validity +50 XP
The Mnemonic: L · I · N · E

For inference on β to be valid (= correct Type I error rate), four conditions must hold:

  • Linear — the relationship between X and Y, if any, is actually linear (not curved, exponential, etc.)
  • Independent — the observations are independent of each other
  • Normal — the residuals \(\epsilon_i \sim N(0, \sigma^2)\) (or n large enough for CLT to make β̂₁ approximately normal)
  • Equal variance — \(\text{Var}(\epsilon_i)\) is the same for all values of X (homoskedasticity)
The Generative Model (what L·I·N·E means formally)

$$y_i = \beta_0 + \beta_1 x_i + \epsilon_i,\qquad \epsilon_i \stackrel{iid}{\sim} N(0,\sigma^2)$$

  • "\(y_i = \beta_0 + \beta_1 x_i + \ldots\)" → Linear
  • "\(\stackrel{iid}{\sim}\)" (independent identically distributed) → Independent
  • "\(N(\ldots)\)" → Normal
  • "\(\sigma^2\)" (one σ², not σᵢ²) → Equal variance
Analogy — Each Letter Has a Price When Broken
  • Break L: your line is the wrong shape entirely → biased β̂₁ AND wrong p-values. Worst.
  • Break I: SE estimates are wrong (usually too small with positive correlation) → inflated false positives.
  • Break N: small-sample p-values can be off; large-sample CLT usually saves you.
  • Break E: SE estimates are wrong (homo-SE formula no longer applies) → wrong p-values.
Two Different N's — Don't Confuse Them

You'll see "Normality of residuals (ε)" stated in Lec 7/10 as the condition. But what we really need for the t-test on β̂₁ is "Normality of β̂₁." Why both? If residuals are normal → β̂₁ is normal exactly (it's a weighted sum of y's). If residuals aren't normal but n is large → β̂₁ is approximately normal by CLT. Either route works.

model1 <- lm(bracket_score ~ knowledge, data=march_madness)

# L & E: residuals vs fitted (should be a flat band)

# N: histogram + Q-Q plot of residuals

Level 32 — Statistical Power for Regression (simulation) +50 XP
Business Story

You're planning the March Madness study. Your hunch: each +1 in knowledge bumps bracket score by ~20 points, with σ ≈ 150 of unexplained noise. How many students do you need to detect this with 80% power? R doesn't have a clean power.t.test() for slopes, so we simulate.

The Four Power Inputs (same as Lec 4)
  1. Effect size — for regression, this is the slope β₁ (and the spread of x)
  2. Variance — σ² of the residuals
  3. Sample size — n (the only knob you usually control)
  4. Significance level — α (almost always 0.05)
R Code — simulation-based power for slope
sim_slope_power <- function(n, beta1, sigma, reps=1000, alpha=0.05) {
  rejects <- numeric(reps)
  for (i in 1:reps) {
    x <- runif(n, 0, 10)                       # predictor
    y <- 623 + beta1 * x + rnorm(n, 0, sigma)   # true model
    fit <- lm(y ~ x)
    p <- summary(fit)$coefficients[2,4]        # slope p-value
    rejects[i] <- (p < alpha)
  }
  mean(rejects)                                  # proportion rejected = power
}

sim_slope_power(n=50, beta1=20, sigma=150)   # ~ 0.80–0.85
Same skeleton as Lec 4's sim_power_t(): simulate data under H_A, run the test, count rejections.
Only the data-generating step changed — now we generate y from x via a linear model, instead of generating x from a single normal.
Want to make the curve? Wrap it in sapply(seq(20, 200, by=20), sim_slope_power, beta1=20, sigma=150).
⚠️ Post-hoc power = mostly useless

If you compute power AFTER you already saw the data and just plug in your sample's β̂₁ and σ̂, it's tautological — it gives high power exactly when p was small. Power calculations are for study design, before data collection. (Same trap as Lec 5's poker example.)

Quiz

"82% of slopes will be statistically significant in the long run, regardless of the truth."
"If the true effect really is β₁=20 with σ=150, then with n=50 students we have an 82% chance of correctly rejecting H₀."
"There's an 82% chance the alternative hypothesis is true."
