Level 9 - Simulating Type I Error: The Master Pattern +70 XP
Business Story

Imagine you are testing 10,000 fire alarms. You KNOW there is no fire (H0 is TRUE). You want to count how many alarms go off anyway (false alarms = Type I Errors). If each alarm is set to alpha = 0.05, you would EXPECT about 500 false alarms out of 10,000 (5%).

In statistics, we do the same thing with SIMULATIONS. We generate fake data where we KNOW H0 is true, run a test, and check if it wrongly rejects. Repeat thousands of times and count the false alarm rate.

Concept - The Four-Step Pattern
  1. Generate fake data where H0 IS TRUE (e.g., rnorm with the claimed mean)
  2. Run a t-test on the fake data
  3. Check if we wrongly reject (is p < alpha?)
  4. Repeat 10,000 times and count how often we wrongly rejected
R Code - Full Type I Error Simulation
set.seed(42)
n <- 30                         # Sample size
n_sims <- 10000                 # Number of simulations
alpha <- 0.05                   # Significance level
mu0 <- 6                        # True mean (H0 IS true)
rejections <- 0                 # Counter for false alarms

for (i in 1:10000) {
  # Step 1: Generate data where H0 is TRUE
  fake_data <- rgamma(n, shape = 2, scale = 3)  # mean = 2*3 = 6 = mu0

  # Step 2: Run t-test
  p_val <- t.test(fake_data, mu = mu0)$p.value

  # Step 3: Check if we wrongly reject
  if (p_val < alpha) {
    rejections <- rejections + 1
  }
}

# Step 4: Calculate Type I Error rate
type1_rate <- rejections / n_sims
print(type1_rate)   # Should be near 0.05 if test works well
n <- 30 - Each fake dataset will have 30 observations.
n_sims <- 10000 - We repeat the experiment 10,000 times.
mu0 <- 6 - The true mean. We generate data with this mean, so H0 is TRUE.
rejections <- 0 - Start counting false alarms at 0.
for (i in 1:10000) - Repeat 10,000 times.
rgamma(n, shape=2, scale=3) - Generate 30 numbers from gamma. Mean = 2*3 = 6 = mu0, so H0 IS true.
t.test(fake_data, mu=mu0)$p.value - Run t-test and grab the p-value.
if (p_val < alpha) - Did we wrongly reject? That is a Type I Error!
rejections / n_sims - Proportion of false alarms. With gamma data, this is often ABOVE 0.05.
Warning - Why Gamma Causes Problems

With gamma data (right-skewed) and n = 30, the Type I Error rate is often around 0.07-0.08 instead of the desired 0.05. This is because the t-test assumes normality, and with small n and skewed data, that assumption is violated. KEY finding from Lab 2!

Level 10 - Bootstrap Confidence Intervals +60 XP
Business Story

You work at a coffee company. You have ONE bag of 50 beans. You want to estimate the average weight. You cannot order more bags (too expensive). So you scoop out 50 beans, weigh them, put them ALL BACK, shake, scoop 50 again, weigh. Repeat 10,000 times. Some beans get weighed multiple times - that is OK! The spread of your 10,000 averages gives you a confidence interval.

Concept — Bootstrap in Plain English

The bootstrap is a way to pretend we have lots of samples when we really only have one. Here is the intuition in three sentences:

  1. In a perfect world we would collect many new samples from the population and watch how much the sample mean bounces around. That tells us the uncertainty.
  2. In real life we only have one sample, so we fake it: we treat our sample AS IF it were the population, and draw new "samples" from it with replacement.
  3. Each fake sample gives a new mean. After 10,000 fake samples we have 10,000 means, and their middle 95% is our 95% confidence interval.

Resampling with replacement means: pick a value, write it down, put it back, pick again. So the same value can show up multiple times in a single bootstrap sample, and some original values may not show up at all. That's what makes each bootstrap sample slightly different.

Three rules of thumb for the bootstrap:

  • Each bootstrap sample is the SAME SIZE as the original sample (if your data has n=8 values, each resample has 8 values too).
  • You use replace = TRUE in sample(). Without that, you'd just get the original data shuffled, which is useless.
  • The bigger the number of bootstrap replicates B, the smoother your CI. B = 10,000 is a common default.
Analogy — Xeroxing the Data

Imagine your sample is a small stack of index cards. The bootstrap says: grab a card, write down its number, put it back, shuffle, grab again. Repeat n times to build one "photocopy" of your dataset. Now compute the mean of that photocopy. Do this 10,000 times and look at the spread of means.

R Code - Bootstrap CI
set.seed(42)
data <- c(12.1, 11.8, 13.2, 12.5, 11.9, 12.8, 13.1, 12.3)
n <- length(data)
B <- 10000                    # Number of bootstrap resamples
boot_means <- rep(0, B)       # Empty vector to store means

for (i in 1:B) {
  # Resample WITH replacement
  boot_sample <- sample(data, n, replace = TRUE)
  # Calculate mean of this resample
  boot_means[i] <- mean(boot_sample)
}

# 95% CI: the middle 95% of bootstrap means
ci <- quantile(boot_means, c(0.025, 0.975))
print(ci)
B <- 10000 - Do 10,000 bootstrap resamples.
boot_means <- rep(0, B) - Create vector of 10,000 zeros to fill.
sample(data, n, replace = TRUE) - Pick n values from data WITH replacement.
boot_means[i] <- mean(boot_sample) - Store the mean of this resample.
quantile(boot_means, c(0.025, 0.975)) - The 2.5th and 97.5th percentiles = 95% CI.
Using CI for Hypothesis Testing

If mu0 is OUTSIDE the 95% CI, reject H0. If mu0 is INSIDE the CI, fail to reject.

Example: CI = [11.9, 12.8]. If H0: mu = 12, since 12 is inside, fail to reject. If H0: mu = 15, since 15 is outside, reject.

Level 11 - The Sign Test: When Data Is Ugly +60 XP
Business Story

You are analyzing Yelp restaurant reviews. Scores are heavily skewed - lots of 5-star reviews, some 1-star, few in between. The mean is misleading. The MEDIAN is better. The t-test would be unreliable with this shape. You need a test that works for ANY distribution shape. That is the sign test.

Concept - The Sign Test Tests MEDIAN, Not Mean

The idea: if the true median is m0, then roughly half the data should be above m0 and half below. If way too many are above (or below), the median is probably not m0. No normality assumption needed!

R Code - Sign Test Function
sign_test <- function(data, m0) {
  # Remove values exactly equal to m0
  data <- data[data != m0]
  n <- length(data)

  # Count how many are above m0
  S <- sum(data > m0)

  # Two-sided p-value using binomial distribution
  p_val <- 2 * min(pbinom(S, n, 0.5), 1 - pbinom(S - 1, n, 0.5))
  return(p_val)
}
data[data != m0] - Remove values that equal the claimed median.
S <- sum(data > m0) - Count values above m0. data > m0 gives TRUE/FALSE, sum() counts TRUEs.
pbinom(S, n, 0.5) - Probability of S or fewer successes in n trials with p = 0.5.
2 * min(...) - Double the smaller tail probability for a two-sided test.
Warning - Discrete p-values

The sign test produces DISCRETE p-values. With n = 7, there are only a few possible p-values. You CANNOT always achieve exactly alpha = 0.05. This is tested in Lab 2!

Level 11b — Lecture 3 Replay: The Sign Test Up Close (and Why Non-Parametric Beats the Gamma) +60 XP
Recap — Where Lecture 3 Picks Up

In Lecture 2, we ran a t-test. In the simulation at the end, we saw that the t-test on gamma-distributed data with n = 5 gave a Type I error rate of about 0.11 — way higher than the nominal 0.05. That's because the t-test's validity hinges on the data being close to normal, and the gamma is heavily skewed.

Lecture 3 asks: is there a test that doesn't care about the data's distribution? Yes — a non-parametric test. "Non-parametric" means: no closed-form null distribution, no normality assumption. The sign test is the one we're going to focus on.

The Key Setup Question (from Poll Everywhere)

The professor asked: if H0: μ = 6 is true, what does the data look like? Students' intuition was "every value equals 6" — but that's way stronger than needed. H0 just needs the mean to be 6; individual values can be spread around it.

What the sign test latches onto is a different, more robust framing of H0: half the values are above 6 and half are below 6. That's a statement about the median, not the mean — which is why the sign test is technically a test of the median (denoted μ̃).

A sign test H0: μ̃ = 6 vs. Ha: μ̃ ≠ 6 says: "each observation is independently 50/50 above or below 6." Under H0, the count above ~ Binomial(n, 0.5).

Gotcha — Mean ≠ Median (Usually)

If the data are symmetric, then mean = median, so a sign test for the median is effectively a test for the mean. If the data are skewed, mean ≠ median, and the sign test is strictly a test for the median.

Always read the question carefully: "test whether the average is..." → t-test or bootstrap. "Test whether the median is..." → sign test. The Quiz 1 language matters.

The Professor's Sign Test Function (Recreated)
# Returns a two-sided sign-test p-value, null hypothesis median = 6
sign_test <- function(x) {
  x <- x[x != 6]                     # drop ties with null
  n <- length(x)
  x_above <- sum(x > 6)

  # two-sided min-tail doubling
  p_low  <- pbinom(x_above, size = n, prob = 0.5)
  p_high <- pbinom(x_above - 1, size = n, prob = 0.5,
                    lower.tail = FALSE)
  min(1, 2 * min(p_low, p_high))
}
Why drop ties? If a value equals the null median exactly, it's neither above nor below. The lecture advice: drop them. (In the simulation, continuous distributions mean ties have probability 0.)
Why min-tail doubling? Binomial(n, 0.5) is symmetric, so two-sided p ≈ 2× the smaller tail — but the outer min(1, ...) clips it so the p-value never exceeds 1.
Why α = 0.0625 for n = 5 (Not 0.05)

With n = 5 and H0: p = 0.5, the most extreme rejection region is {X = 0} ∪ {X = 5} (all above or all below).

P(X = 0) = 0.5⁵ = 0.03125. By symmetry, P(X = 5) = 0.03125 too.

So the smallest non-empty two-sided rejection region has α = 0.03125 + 0.03125 = 0.0625.

You cannot achieve exactly 0.05 with n = 5. You either use {0, 5} with α = 0.0625, or you use {} (the empty set) with α = 0 (but you'd never reject anything). The lecture convention: use the rejection region closest to 0.05 — here, {0, 5} with α = 0.0625.

Coding detail: The professor added a small ε bump (0.0626) so that when the simulated p-value equals 0.0625 exactly, the comparison p_value < alpha still rejects.

Contrast: t-test on the same gamma data gave Type I error ≈ 0.11. Sign test gives ≈ 0.0625, which is exactly the nominal level. This is the headline result of Lecture 3.

Bootstrap CI as a Non-Parametric Test for the MEAN

The sign test lets you test a median without any distribution assumption. But what if you specifically care about the mean and your data is skewed? Enter the bootstrap.

A 95% bootstrap CI for the mean is a (roughly) α = 0.05 two-sided test of H0: μ = μ₀: if μ₀ is outside the CI, reject; otherwise, fail to reject.

Level 12 - Statistical Power: Can You Detect the Signal? +50 XP
Business Story — The Metal Detector

Imagine a metal detector at the beach. Your ability to find treasure depends on:

  • How big the object is (big ring vs tiny earring) = effect size (delta)
  • How deep it is buried (noise) = sigma
  • How sensitive your detector is = alpha
  • How long you search = sample size (n)

Power = the probability that your detector finds the treasure, assuming there really IS treasure.

Concept — What Power Actually Is

Power = P(reject H0 | H0 is false). In words: if the claim is actually wrong, how often will our test correctly notice?

Compare this with Type I Error: Type I Error = P(reject H0 | H0 is true). Same test, different assumption about reality.

  • Type I Error: we fake data where H0 is TRUE and count false alarms. Want this low.
  • Power: we fake data where H0 is FALSE and count correct detections. Want this high.

Power ranges from 0 to 1. Higher is better. 0.80 is the conventional target.

Concept — Mean, Effect Size, and Power (The Key Quiz 1 Relationship)

This is the thing most students get confused about. Keep this picture in your head:

  • mu0 = the claimed mean (the null value you are testing against).
  • true mean = the real population mean (what actually generates the data).
  • delta (effect size in raw units) = the GAP: true mean − mu0.

So if the airport claims mu0 = 20 minutes but the true average is 50, then delta = 50 − 20 = 30. When you simulate power, you generate data with mean = mu0 + delta, which here means mean = 50. You then test that data against mu0 = 20 and see how often you (correctly) reject.

The bigger delta is relative to the noise sigma, the easier it is to detect, so power goes up. This is why power is often summarized through the standardized effect size d = delta / sigma (Cohen's d).

Plain English for Quiz 1:

  • Tiny gap between mu0 and the truth → hard to detect → low power.
  • Big gap between mu0 and the truth → easy to detect → high power.
  • Noisy data (big sigma) hides the gap → low power. Tight data (small sigma) exposes the gap → high power.
  • More data (big n) shrinks the standard error sigma/sqrt(n) → high power.
Four Dials That Turn Power Up or Down
  1. n (sample size) ↑ → power ↑. More data makes the sampling distribution narrower.
  2. delta (true gap from mu0) ↑ → power ↑. Bigger effect is easier to catch.
  3. sigma (standard deviation of the data) ↓ → power ↑. Less noise, clearer signal.
  4. alpha (significance level) ↑ → power ↑, but you also get more false alarms. Usually fixed at 0.05.

Quiz 1 intuition check: Practice Quiz 1 Q2 asks about power when delta = 30 and sigma = 10 — a HUGE gap relative to the noise. No surprise that power is 0.9999.

Level 12b — Lecture 4 Replay: Power Deep Dive (Bert, Ernie, and Why Simulation Wins) +70 XP
Definition — Power, Formally

Power = P(reject H0 | Ha is true). It's the probability your test correctly flags a real effect.

Compare to Type I error, which is P(reject H0 | H0 is true). Same verb ("reject H0"), opposite condition. A statistical test is juggling both — it wants to reject when H0 is false (high power) and NOT reject when H0 is true (low Type I error).

Rule of thumb from lecture: 80% power is the industry-standard target. Higher is better. Below 50% power, your study is flipping a coin to detect a real effect.

The Four Dials (Memorize Directions!)

Power is a function of exactly four things. Know which direction each moves it:

DialNotationEffect on Power
Sample sizen↑ n → ↑ power
Significance levelα↑ α → ↑ power (but more Type I)
Standard deviationσ↑ σ → ↓ power
Effect size|μ − μ₀| (or δ)↑ effect → ↑ power

Intuition checks from lecture:

  • Lowering α from 0.05 to 0.01 makes rejection harder ⇒ power drops.
  • If every UCSD student slept exactly 5.5 hrs (no variability), it'd be obvious the mean isn't 6. Add noise (high σ), and 5.5 gets muddled with 6.
  • An effect size of 2 (true mean = 4 when μ₀ = 6) is easy to detect. Effect size of 0.5 (true mean = 5.5) is hard.
The Chicken-and-Egg Problem

Here's the deep issue the lecture surfaces: power depends on σ and effect size. But σ and effect size are properties of the real population — the very thing you don't know yet (that's why you're doing a study!).

Three ways out:

  1. Literature review. Find a similar study's σ and plausible effect, plug those in.
  2. Pilot study. Collect a small preliminary sample, use its σ and observed effect as estimates.
  3. Post-hoc power. Compute power after the study. The professor strongly dislikes this. Either you rejected H0 (so you had "enough" power) or you didn't (and post-hoc numbers can't save the study). It's treated as uninformative.

Exam tip: If asked to rank the three approaches, put literature review / pilot study as "acceptable" and post-hoc as "least desirable / not recommended."

The Non-Central t Distribution (Bert & Ernie)

Under H0: μ = 6, the t-statistic (x̄ − 6)/(s/√n) follows a standard t-distribution centered at 0. This is "Bert" — tall, narrow, centered.

Under Ha: μ = 4 (the lecture's example), the t-stat is still computed the same way, but now it follows a non-central t distribution — shifted AND slightly flattened/widened. This is "Ernie" — shorter, wider, shifted left.

Power is the area under Ernie that falls in Bert's rejection region. Graphically: the non-central t's lower tail beyond the critical value −2.776.

The non-centrality parameter is: 

ncp = (μ - μ₀) / (σ / sqrt(n))
It's the "distance in SE units" between the two distributions' centers.

Theory-Based Power (Manual Calculation)
# Scenario: n=5, σ=1, μ₀=6, true μ=4, α=0.05 (two-sided)
n <- 5
sigma <- 1
mu0 <- 6
mu_true <- 4

# Lower critical value of the null distribution
crit <- qt(0.025, df = n - 1)     # ≈ -2.776

# Non-centrality parameter
ncp <- (mu_true - mu0) / (sigma / sqrt(n))   # ≈ -4.47

# Power = P(T_ncp < crit) under the non-central t
power <- pt(crit, df = n - 1, ncp = ncp)
power
# ≈ 0.908
What pt(..., ncp = ...) does: gives you the lower-tail probability under a non-central t distribution. Without ncp, it defaults to the standard t (ncp = 0).
The upper-tail part of power (area beyond +2.776 under Ernie) is microscopic here and we ignore it. For bigger ncp's, you might want to add it.
The Built-In Shortcut — power.t.test()
power.t.test(n = 5,
             delta = 2,              # |μ_true - μ₀| = |4 - 6|
             sd = 1,
             sig.level = 0.05,
             type = "one.sample",
             alternative = "two.sided")
# power ≈ 0.908 — same answer
Leave EXACTLY ONE of n, delta, sd, sig.level, power as NULL. R solves for whichever is missing.
type = "one.sample" for one-sample; "two.sample" for two-sample; "paired" for paired.
delta is the absolute effect size. Use positive numbers even for "less than" alternatives.
Solving for n: leave n = NULL and supply power = 0.80. The returned n may be fractional — always round UP.
Why Simulation Beats Theory (4 Reasons from Lecture)
  1. Easier to understand. Non-central t is confusing. Simulation is just "generate data under Ha, run the test, count rejections."
  2. Less memorization. power.t.test() has specific syntax you forget. Simulation uses the same rnorm/t.test patterns you already know.
  3. Generalizes. power.t.test() only works for t-tests. Simulation works for ANY test — sign test, regression, bootstrap — just swap the test function.
  4. Not tied to normal data. power.t.test() assumes the data is normal under Ha. Simulation can use rgamma, runif, or anything else.
Simulation-Based Power (The Master Pattern)
set.seed(42)
B <- 10000
n <- 5
mu0 <- 6
mu_true <- 4
sigma <- 1
reject <- logical(B)

for (b in 1:B) {
  # KEY: generate under Ha (mu_true), NOT under H0 (mu0)
  samp <- rnorm(n, mean = mu_true, sd = sigma)
  pval <- t.test(samp, mu = mu0)$p.value
  reject[b] <- pval < 0.05
}
mean(reject)
# ≈ 0.907 — matches the theory value
The ONE line that separates Type I from power: the mean in rnorm. mean = mu0 → Type I sim. mean = mu_true (≠ mu0) → power sim. Everything else is the same structure.
Don't forget mu = mu0 inside t.test. That's the null value we're testing against, NOT the data-generating mean.

}

Level 13 - Simulating Power in R +60 XP
Key Difference from Type I Simulation

Type I Error sim: generate data where H0 is TRUE (mean = mu0).
Power sim: generate data where H0 is FALSE (mean = mu0 + delta).

R Code - Power Simulation
set.seed(42)
n <- 30
n_sims <- 10000
mu0 <- 10                # Claimed mean under H0
delta <- 2                # True effect: real mean is 12
true_mean <- mu0 + delta  # = 12
rejections <- 0

for (i in 1:n_sims) {
  # Generate data where H0 is FALSE
  fake_data <- rnorm(n, mean = true_mean, sd = 5)

  # Test against mu0
  p_val <- t.test(fake_data, mu = mu0)$p.value

  if (p_val < 0.05) {
    rejections <- rejections + 1
  }
}

power <- rejections / n_sims
print(power)
true_mean <- mu0 + delta - Real mean is 12, NOT 10. H0 (mu = 10) is FALSE.
rnorm(n, mean = true_mean, sd = 5) - Generate data from the TRUE distribution.
rejections / n_sims - Proportion of correct rejections = estimated power.

sim_power <- function(n, delta, sd, alpha = 0.05, reps = 10000) {
  count <- 0
  for (i in 1:reps) {
    samp  <- rnorm(n = n,
                    mean = 20 + delta,   # mu0 + delta = TRUE mean
                    sd   = sd)
    pval  <- t.test(samp, mu = 20)$p.value
    if (pval < alpha) {
      count <- count + 1
    }
  }
  return(count / reps)
}
This is the Practice Quiz 1 Q6 pattern. The blanks they ask about are always: n = n, mean = mu0 + delta, sd = sd, if(pval < alpha), and return(count / reps).
mu0 + delta is the true mean. We test against mu = 20 which is mu0. Every rejection here is a CORRECT rejection because the truth is 20 + delta ≠ 20.
count / reps is the estimated power: the fraction of simulated datasets where the t-test correctly rejects.

Level 14 - The Big Data Trap +40 XP
Business Story

You work at Spotify. Your team finds playlist A has 180.3 seconds average listen time, playlist B has 180.0. Difference: 0.3 seconds. Sample: 50 MILLION users. p-value: 0.00001.

Should you redesign the app around playlist A? No! 0.3 seconds is meaningless. But with 50 million data points, even a tiny difference becomes "statistically significant."

Statistical Significance vs Practical Significance

With large n, ANY tiny difference becomes statistically significant. A small p-value only tells you "this difference is probably real." It does NOT tell you "this difference MATTERS."

Always check: (1) p-value, (2) effect size, (3) confidence interval width.

Level 15 - Cohen's d: Measuring Effect Size +40 XP
Formula

d = |x_bar - mu0| / s

Rough guidelines: d = 0.2 (small), d = 0.5 (medium), d = 0.8 (large)

R Code - Cohen's d
cohens_d <- function(data, mu0) {
  d <- abs(mean(data) - mu0) / sd(data)
  return(d)
}

data <- c(23, 25, 28, 22, 30, 27)
cohens_d(data, 20)
