Level 50 — Hypothesis Testing 101 (H₀, H_A, p-value) +90 XP
🧠 Simple Explanation

You have a guess about the world. You collect data. You ask: "If my guess is wrong, would I see numbers like these?"

If the data looks weird under the wrong guess, you reject the guess. If the data looks normal under the wrong guess, you keep the guess.

That is hypothesis testing. One guess. One question. One answer.

📐 Math Language
  • Null hypothesis \(H_0\): the "boring" claim. Usually "no effect" or "equal to zero".
  • Alternative hypothesis \(H_A\): the "interesting" claim. The thing you suspect.
  • Test statistic: a number computed from data (e.g. \(t_s = (\bar x - \mu_0) / (s/\sqrt n)\)).
  • p-value: \(P(\text{test stat at least this extreme} \mid H_0 \text{ true})\).
  • Significance level \(\alpha\): the cutoff (usually 0.05). If \(p < \alpha\), reject \(H_0\).
🔗 Connection — Simple ↔ Math
Simple IdeaMath Language
"My boring guess"\(H_0\) (null hypothesis)
"My interesting guess"\(H_A\) (alternative hypothesis)
"How weird is my data, assuming the boring guess?"p-value
"My weirdness threshold"\(\alpha\) (significance level, usually 0.05)
"Reject the boring guess""reject \(H_0\) at the \(\alpha = 0.05\) level"
"Cannot reject the boring guess""fail to reject \(H_0\)" (NOT "accept \(H_0\)")
🍎 Intuitive Example — Coin Flip

You suspect a coin is unfair. You flip it 6 times and get 6 heads.

  1. Boring guess (\(H_0\)): coin is fair, \(p = 0.5\).
  2. Interesting guess (\(H_A\)): coin is not fair, \(p \neq 0.5\).
  3. If the coin IS fair, P(6 heads in 6 flips) = \((0.5)^6\) = 0.0156. P(0 heads) = 0.0156. Two-sided p-value ≈ 0.031.
  4. 0.031 < 0.05 → reject \(H_0\). Coin is unfair.

  3. Forgetting the two-sided ×2 — for a two-sided test you double the one-sided p-value (or use the two-tail probability directly).
Level 51 — Type I & Type II Errors +90 XP
🧠 Simple Explanation

Every test can be wrong in two ways:

  • Type I: you think there IS an effect, but there isn't. (False alarm.)
  • Type II: you think there is NO effect, but there is. (Missed it.)

Like a smoke alarm: Type I = beeps when no fire. Type II = silent during a fire.

📐 Math Language
  • Type I error rate: \(\alpha = P(\text{reject } H_0 \mid H_0 \text{ true})\). Usually fixed at 0.05.
  • Type II error rate: \(\beta = P(\text{fail to reject } H_0 \mid H_A \text{ true})\).
  • Power: \(1 - \beta = P(\text{reject } H_0 \mid H_A \text{ true})\). The "good" probability.
  • Validity: a test is valid if its actual Type I rate equals its nominal \(\alpha\).
🔗 Connection
\(H_0\) is TRUE\(H_0\) is FALSE
We REJECT \(H_0\)Type I (false alarm)
Probability = α		Correct!
Probability = 1 − β = power
We FAIL to reject \(H_0\)Correct!
Probability = 1 − α		Type II (miss)
Probability = β

"False alarm rate" = α  ·  "Miss rate" = β  ·  "Hit rate" = 1 − β = power

🍎 Intuitive Example — Spam Filter

Email "is spam" or "is not spam." Filter says "spam" or "not spam."

  • Type I (false positive): legit email goes to spam folder.
  • Type II (false negative): real spam reaches inbox.
  • Lowering α (be picky) → fewer Type I, but more Type II.
  • Raising α → catch more real spam, but more legit emails get filtered.

Most filters use ~α = 0.01 (only 1% of safe emails get flagged).

  3. Believing α = 0 is best. α = 0 means you NEVER reject — your test has no power at all.
Level 52 — The One-Sample t-Test +90 XP
🧠 Simple Explanation

You measured a number for n people (sleep hours, test scores, anything). You want to know: "Is the average really different from some target value?"

The t-test compares (your average − target) to (how spread out your data is). If the difference is big and the spread is small, you reject the boring guess.

📐 Math Language
  • Hypotheses: \(H_0: \mu = \mu_0\) vs \(H_A: \mu \neq \mu_0\).
  • Test statistic: \(t_s = \dfrac{\bar x - \mu_0}{s/\sqrt n}\)
  • Standard error of the mean: \(SE(\bar x) = s / \sqrt n\)
  • Null distribution: \(t_s \sim t_{n-1}\) (t-distribution with n − 1 degrees of freedom).
  • p-value (two-sided): \(2 \cdot P(|T_{n-1}| \geq |t_s|)\)
🔗 Connection
Simple IdeaMath Language
"How far is my mean from the target?"numerator: \(\bar x - \mu_0\)
"How spread out is my sample?"\(s\) = sample standard deviation
"How precise is my mean estimate?"\(SE(\bar x) = s/\sqrt n\) — shrinks as n grows
"Many SEs away from the target"\(t_s\) (units: standard errors)
"How many SEs is too many?"compare \(|t_s|\) to critical value from \(t_{n-1}\)
🍎 Intuitive Example — UCSD Sleep

5 students report sleep: 3, 7, 1, 2, 2 hours. Target: \(\mu_0 = 6\) (recommended).

  1. \(\bar x = (3+7+1+2+2)/5 = 3\)
  2. \(s = 2.55\) (compute from variance)
  3. \(SE = 2.55/\sqrt 5 = 1.14\)
  4. \(t_s = (3 - 6)/1.14 = -2.63\)
  5. df = 4. Two-sided p ≈ 0.058 → fail to reject at α = 0.05 (just barely).

Level 53 — Bootstrap CIs vs Permutation Tests +90 XP
🧠 Simple Explanation

Both methods use resampling. Both build a fake distribution from your real data. But they answer DIFFERENT questions.

  • Bootstrap: "How precise is my estimate?" → builds a confidence interval.
  • Permutation: "Could this difference be by chance?" → builds a p-value for two-group comparison.

Same recipe (sample, repeat, summarize). Different goal.

📐 Math Language
  • Bootstrap: sample WITH replacement from data, recompute statistic, repeat. CI = quantiles of bootstrap distribution.
  • Permutation: shuffle group labels (sample WITHOUT replacement), recompute test statistic, repeat. p-value = fraction at least as extreme as observed.
  • Bootstrap CI (percentile): \([\hat\theta_{(0.025)}, \hat\theta_{(0.975)}]\) — 2.5th and 97.5th percentiles of bootstrap stats.
  • Permutation p: \(\hat p = \dfrac{1}{B}\sum_{b=1}^B \mathbb{1}\{|T_b^*| \geq |T_{\text{obs}}|\}\)

🍎 Intuitive Example

Bootstrap (CI for mean sleep): data = c(3,7,1,2,2). Resample 1000 times WITH replacement, compute mean each time. The 2.5th and 97.5th percentiles ≈ (1.4, 5.0) = your 95% CI.

Permutation (handwritten vs coding): data = c(2,5,3,-3,8) and c(9,10,-1,14,6). Observed mean diff = 4.6. Shuffle labels 1000 times. Count how often |shuffled diff| ≥ 4.6. Say 110 of 1000 → p = 0.11. Fail to reject.

🎮 Interactive — Build the right loop in R

For BOOTSTRAP CI of the mean (single sample):

x <- c(3,7,1,2,2)
boot_means <- numeric(1000)
for (i in 1:1000) {
  resample <- sample(x, length(x), replace=TRUE)  # ← WITH replacement
  boot_means[i] <- mean(resample)
}
quantile(boot_means, c(0.025, 0.975))

For PERMUTATION (two-sample):

obs_diff <- mean(group1) - mean(group2)
combined <- c(group1, group2)
n1 <- length(group1)
perm_diffs <- numeric(1000)
for (i in 1:1000) {
  shuffled <- sample(combined)                     # ← WITHOUT replacement (default)
  perm_diffs[i] <- mean(shuffled[1:n1]) - mean(shuffled[(n1+1):length(shuffled)])
}
mean(abs(perm_diffs) >= abs(obs_diff))

Level 54 — Statistical Power +90 XP
🧠 Simple Explanation

Power is the probability your test will FIND a real effect when one exists. High power = good test. Low power = your test misses real things often.

Power depends on: sample size, effect size, noise, and α.

📐 Math Language
  • Power \(= 1 - \beta = P(\text{reject } H_0 \mid H_A \text{ true})\)
  • Four inputs: sample size \(n\), effect size \(\delta = |\mu_A - \mu_0|\), residual SD \(\sigma\), significance \(\alpha\).
  • Effect size (standardized): Cohen's d = \(\delta / \sigma\). d ≈ 0.2 small, 0.5 medium, 0.8 large.
  • Power formula (one-sample t): \(P(T \geq t_{\alpha/2, n-1} \mid \text{ncp} = \delta\sqrt n / \sigma)\) where T is non-central t.
  • R command: power.t.test(n, delta, sd, sig.level, type="one.sample")

"More noise = harder to spot"Power decreases with \(\sigma\)

"My test missed it"Type II error (probability β = 1 − power)
🍎 Intuitive Example — Detect a 5% sleep deficit

Truth: \(\mu_A = 6.7\), \(\mu_0 = 7.0\). So \(\delta = 0.3\) hours. Suppose \(\sigma = 1.0\), \(\alpha = 0.05\).

  • n = 20: power ≈ 0.27 (you'll miss the effect 73% of the time!)
  • n = 100: power ≈ 0.86
  • n = 200: power ≈ 0.99

Same effect, different ability to detect, all due to sample size.

Level 55 — The Big Data Trap (Significance ≠ Importance) +100 XP
🧠 Simple Explanation

With huge n, even tiny differences become "statistically significant." But "significant" doesn't mean "important."

Example: A study of 10 million people shows the new shoe makes you 0.0001 seconds faster. p < 0.0001. But who cares?

Always ask: does the effect matter in the real world?

📐 Math Language
  • Statistical significance: \(p < \alpha\). Probability-based.
  • Practical significance: the effect is large enough to matter in context. Domain-based.
  • Effect size: \(\delta\), Cohen's d, raw difference, etc. Always report alongside p.
  • Confidence interval: gives RANGE of plausible effects — better than just p-value when n is huge.
  • Power inflation: as \(n \to \infty\), even \(\delta \to 0\) gives power → 1.
🔗 Connection
SimpleMath
"Tiny but real difference"Small δ, p < α at huge n
"Real and meaningful"Big δ, narrow CI excludes 0 by a lot
"Real but irrelevant"p < 0.001, effect size = 0.0001
"CI narrow and away from 0"Effect is precisely estimated AND practically important
"With huge n, all effects detectable"\(n \to \infty\) ⇒ power → 1 for any \(\delta > 0\)
🍎 Intuitive Example — Bacon and Cancer

News headline: "Bacon increases cancer risk by 18%!" Sounds scary.

The actual numbers: baseline colon cancer risk = 5%. Eating bacon daily: 5% × 1.18 = 5.9% — an absolute increase of 0.9 percentage points.

Statistically: p < 0.001. Practically: most people might prefer the bacon.

Always show absolute and relative effects together.

🎮 Interactive — Big-N Demo
# Tiny effect, huge sample
set.seed(42)
n <- 50000; mu_true <- 5.01; mu_0 <- 5.00; sigma <- 1
x <- rnorm(n, mean=mu_true, sd=sigma)
t.test(x, mu=mu_0)$p.value
# [1] 0.025  ← "significant"

t.test(x, mu=mu_0)$conf.int
# [1] 5.001 5.018  ← effect is real but TINY (0.01 to 0.018)
# Practical importance? Probably none.

The takeaway: always check the CI, not just p.
